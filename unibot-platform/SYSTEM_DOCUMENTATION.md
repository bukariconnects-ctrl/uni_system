# UniBot — توثيق شامل للنظام

> **وُضع هذا التوثيق بقلم المهندس المطوّر للنظام** — وصف دقيق لكل طبقة من طبقات المنصة، من فلسفة الهندسة إلى أدق تفاصيل واجهة المستخدم.

---

## 1. ما هو UniBot؟

**UniBot** هو نظام إدارة جامعية (LMS / University Management System) متعدد المستأجرين (Multi-Tenant SaaS) مبني على تقنيات حديثة. يُمكّن المنصةَ من استضافة عدد غير محدود من الجامعات على بنية تحتية موحّدة، مع عزل كامل للبيانات بين كل مؤسسة وأخرى.

يقدّم النظام حلاً متكاملاً يغطي دورة الحياة الأكاديمية بالكامل:

- **إدارة الهيكل الأكاديمي**: كليات، أقسام، تخصصات، مستويات
- **إدارة المستخدمين**: طلاب، محاضرون، إدارة أكاديمية، مدير جامعة
- **إدارة المقررات والخطط الدراسية والمتطلبات السابقة**
- **إدارة الفصول الدراسية والشعب والتسجيل والجداول**
- **أتمتة الحضور بتقنية QR Code**
- **دفتر الدرجات وإدارة التكاليف**
- **نظام تعميمات وقنوات تواصل فوري**
- **نظام تذاكر دعم ذكي (AI-powered)**
- **مساعد ذكاء اصطناعي (UniBot AI) مرتبط بقاعدة معرفة المؤسسة**
- **تحليلات الخطورة الأكاديمية (Risk Analytics)**
- **بوابة محاضرات ومواد تعليمية**

## 2. الهندسة التقنية

### Stack التقني

| الطبقة | التقنية |
|--------|---------|
| Frontend Framework | **Next.js 14** — App Router + Server Components |
| Language | **TypeScript** — صارم بالكامل |
| Styling | **Tailwind CSS** — نظام ألوان ومكونات مخصص |
| Backend / Database | **Supabase** (PostgreSQL + Row Level Security) |
| Auth | **Supabase Auth** — JWT + Sessions |
| Realtime | **Supabase Realtime** — Postgres Changes |
| AI Engine | **Custom AI API Route** — `/api/ai/chat` |
| AI Responses | **ReactMarkdown + remark-gfm** |
| QR Scanning | **@yudiel/react-qr-scanner** |
| Icons | **Lucide React** |

### نموذج Multi-Tenant

كل سجل في قاعدة البيانات يحمل حقل `tenant_id` مما يضمن عزلاً كاملاً بين الجامعات. تُطبَّق قواعد **Row Level Security (RLS)** على مستوى Supabase لمنع أي تسرّب للبيانات بين المستأجرين.

### هيكل التطبيق

```
src/
├── app/
│   ├── super-admin/        # لوحة تحكم المشغّل الرئيسي للمنصة
│   ├── tenant-admin/       # لوحة تحكم مدير الجامعة
│   ├── academic-management/ # لوحة الإدارة الأكاديمية
│   ├── faculty/            # بوابة أعضاء هيئة التدريس
│   ├── student/            # بوابة الطلاب
│   ├── api/ai/chat/        # نقطة نهاية AI
│   └── login/              # صفحة الدخول
├── components/             # مكونات مشتركة (Sidebar, Layout...)
└── lib/
    ├── auth/               # منطق التحقق من الصلاحيات
    ├── supabase/           # عملاء Supabase (client/server/service)
    └── types/              # تعريفات TypeScript للقاعدة
```

## 3. الأدوار في النظام

| الدور | الرمز | الوصف |
|-------|-------|-------|
| مدير المنصة | `super_admin` | يملك ويُشغّل المنصة بالكامل |
| مدير الجامعة | `tenant_admin` | يُدير كل إعدادات الجامعة |
| إدارة أكاديمية | `academic_management` | عمداء، رؤساء أقسام، سكرتارية |

## 4. العمليات التفصيلية بحسب الفاعل

### 🌐 مدير المنصة (Super Admin)

#### 4.1 إدارة خطط الاشتراك
- **ينشئ** خطط اشتراك (أساسي / احترافي / مؤسسي) بتحديد:
  - السعر الشهري
  - الحد الأقصى للمستخدمين
  - مساحة التخزين (GB)
- **يعدّل** أو **يحذف** الخطط في أي وقت

#### 4.2 إنشاء جامعة جديدة (Wizard ثلاثي الخطوات)
- **الخطوة 1**: بيانات الجامعة
  - اسم الجامعة
  - النطاق الفرعي (subdomain.unibot.app)
  - بريد وبيانات مدير الجامعة
- **الخطوة 2**: اختيار خطة الاشتراك + تخصيص حصص المستخدمين والتخزين
- **الخطوة 3**: مراجعة ونشر — يُنشئ النظام تلقائياً: حساب المدير + سجل الجامعة + الاشتراك

#### 4.3 إدارة حالة الجامعات
- **تفعيل** (active): تُصبح الجامعة نشطة وعاملة
- **تعليق** (suspended): يُمنع جميع المستخدمين من الوصول
- **وضع تجريبي** (trial): فترة تجربة محدودة
- **حذف** (deleted): حذف منطقي لا رجعة منه

#### 4.4 تعديل الحصص
- يُعدّل الحد الأقصى للمستخدمين والتخزين لكل جامعة بشكل مستقل

#### 4.5 لوحة المراقبة
- إجمالي الجامعات + تصنيفها حسب الحالة
- استخدام التخزين الكلي (نسبة من المجموع)
- استهلاك AI Tokens + التكلفة الإجمالية بالدولار
- الإيرادات المحصّلة والفواتير المتأخرة

#### 4.6 إدارة الإعلانات
- ينشر إعلانات على مستوى المنصة بالكامل

### 🏛️ مدير الجامعة (Tenant Admin)

#### 4.7 بناء الهيكل الأكاديمي (شجرة رباعية المستويات)

```
الجامعة
└── كلية (College)
    └── قسم (Department)  ← يمكن تعيين رئيس قسم
        └── تخصص (Major)  ← إجمالي الساعات + مدة الدراسة بالسنوات
            └── مستوى أكاديمي (Academic Level)  ← السنة الأولى / الثانية...
```

**العمليات على كل مستوى:**
- إنشاء / تعديل / حذف
- ربط رئيس القسم (عضو هيئة تدريس)

#### 4.8 إدارة المستخدمين

**إضافة فردية:**
- يملأ بيانات المستخدم (الاسم، البريد، الدور، الرقم الجامعي أو رقم الموظف، القسم، التخصص، المستوى)
- يُحدد الحالة: نشط / معلّق / منتهي

**استيراد جماعي (CSV):**
- يرفع ملف CSV بالتنسيق المحدد
- يعالج النظام الصفوف تلقائياً ويُرجع تقرير النجاح والأخطاء

**تبويبات إدارة المستخدمين:**
- الكل / الطلاب / أعضاء هيئة التدريس / الإدارة الأكاديمية

**إجراءات على المستخدم:**
- عرض الملف الشخصي الكامل
- تعديل البيانات
- تغيير الحالة (تعليق / إعادة تفعيل)
- حذف الحساب

#### 4.9 إدارة المقررات

**تبويب كتالوج المقررات:**
- إنشاء مقرر: الكود، الاسم، الساعات المعتمدة، النوع (إلزامي/اختياري)، القسم
- تعديل / حذف المقررات

**تبويب الخطة الدراسية:**
- ربط المقررات بالمستويات الأكاديمية ضمن الخطة الدراسية
- إزالة مقرر من الخطة

**تبويب المتطلبات السابقة:**
- تحديد شرط المقرر (ما يجب أن يجتازه الطالب قبل التسجيل)
- حذف شرط مسبق

#### 4.10 إدارة التقويم الأكاديمي (الفصول الدراسية)

**إنشاء فصل دراسي:**
- الاسم، النوع (أول / ثانٍ / صيفي)، تاريخ البداية والنهاية

**دورة حياة الفصل:**
```
تخطيط (planning)
    ↓
تسجيل (registration)  ← يُتاح للطلاب التسجيل
    ↓
نشط (active)  ← تبدأ المحاضرات
    ↓
تجميد الدرجات (grade_freeze)  ← نهاية الفصل، الدرجات محمية
    ↓
مؤرشف (archived)
```

#### 4.11 إدارة المبنى / القاعات (Venues)
- إضافة قاعة دراسية: الاسم، الكود، النوع (قاعة محاضرة / مختبر / قاعة دراسة)
- تحرير / حذف القاعات

#### 4.12 قاعدة المعرفة (لـ UniBot AI)
- رفع مستندات PDF (لوائح / أدلة / سياسات / مواد تعليمية)
- تفعيل/تعطيل مستند من استخدامه في الاستجابات
- إعادة فهرسة (Reindex) المستند عند تحديثه
- حذف المستند من القاعدة

**أنواع المستندات:**
- `regulation` — لوائح
- `handbook` — دليل الطالب
- `policy` — سياسات
- `course_material` — مادة تعليمية
- `other` — أخرى

#### 4.13 إعدادات الجامعة
- **العلامة التجارية**: رابط الشعار، اللون الرئيسي
- **التوطين**: المنطقة الزمنية، اللغة الافتراضية
- **نسبة الحرمان**: الحد الأقصى للغياب المسموح به (%)

### 📋 الإدارة الأكاديمية (Academic Management)

#### 4.14 إدارة الشعب الدراسية

**إنشاء شعبة:**
- اختيار المقرر + الفصل الدراسي + الحد الأقصى للطلاب

**تعيين المحاضر:**
- ربط شعبة بعضو هيئة تدريس

**تغيير حالة الشعبة:**
- مفتوحة (open) / مغلقة (closed) / مؤرشفة (archived) / مدمجة (merged)

**دمج الشعب:**
- دمج شعبة في أخرى من نفس المقرر عند انخفاض الأعداد

#### 4.15 إدارة التسجيل

**تسجيل جماعي:**
- اختيار شعبة → اختيار الطلاب من القائمة → تسجيل دفعة واحدة
- فحص الطاقة الاستيعابية تلقائياً

**سجل التسجيلات:**
- عرض جميع التسجيلات مع حالاتها
- تحديث الحالة: مسجل / منسحب / مكتمل / راسب / مفصول / انسحاب كلي

#### 4.16 إدارة الجداول الدراسية

**إنشاء حصة في الجدول:**
- اختيار الشعبة + اليوم + وقت البداية والنهاية + القاعة

**تغيير حالة الحصة:**
- مسوَّدة (draft) → منشورة (published) ← تظهر في جداول الطلاب
- أو إلغاؤها (cancelled)

**تعديل وحذف الحصص**

#### 4.17 تحليلات الخطورة الأكاديمية

**تشغيل حساب الخطورة (Risk Computation):**
- يُحرّك النظام خوارزمية تحسب درجة خطورة كل طالب بناءً على:
  - `absence_factor` — معدل الغياب
  - `grade_factor` — مستوى الدرجات
  - `engagement_factor` — مستوى التفاعل
- يُصنَّف الطلاب: منخفض / متوسط / مرتفع / حرج

**مراقبة المقررات المُعلَّمة (Course Flags):**
- المقررات التي بها نسبة رسوب عالية أو متوسط خطورة مرتفع
- إرسال توصية مُباشرة للمحاضر المسؤول

#### 4.18 التعاميم
- إرسال تعاميم لطلاب / محاضرين / أقسام محددة
- عرض التعاميم المرسلة والمستلمة

#### 4.19 التذاكر (دعم الطلاب)
- عرض تذاكر الطلاب الواردة
- الرد والتواصل
- تغيير الحالة: مفتوح / قيد المعالجة / بانتظار معلومات / محلول / مغلق / مرفوض

### 👨‍🏫 المحاضر (Faculty)

#### 4.20 المواد التعليمية

**رفع مادة:**
- النوع: PDF / فيديو / عرض تقديمي / مستند / صوتي / رابط / أخرى
- عنوان المادة + وصف + ربطها بشعبة محددة + تفعيل للطلاب
- تفعيل موافقة AI للاستخدام في UniBot

**إدارة المواد:**
- نشر / إخفاء عن الطلاب
- حذف المادة

**خطط المقررات (Syllabi):**
- إنشاء خطة أسبوعية للمقرر (الأسبوع، الموضوع، المحتوى)
- تقديم الخطة للاعتماد الأكاديمي
- حالات الخطة: مسودة → مُقدَّمة → معتمدة / مرفوضة

#### 4.21 التكاليف والواجبات

**إنشاء تكليف:**
- العنوان، الوصف، الموعد النهائي، الشعبة، درجة الرصيد
- نشر / إخفاء عن الطلاب

**متابعة التسليمات:**
- عرض تسليمات الطلاب
- تصفية بالحالة: مُسلَّم / متأخر / مُصحَّح / مطلوب إعادة

**تصحيح التكليف:**
- إدخال الدرجة مع ملاحظات للطالب

**طلب إعادة التسليم:**
- إعادة التكليف للطالب مع تعليق التصحيح

#### 4.22 الحضور والغياب

**إنشاء جلسة حضور:**
- اختيار الشعبة + التاريخ + وصف اختياري

**تسجيل الحضور (وضعان):**

*الوضع اليدوي:*
- تصفح قائمة الطلاب وتحديد: حاضر / غائب / متأخر / معذور

*وضع QR Code:*
- ينشئ النظام رمز QR مؤقت (يُجدَّد كل 10 ثوانٍ لمنع التزوير)
- يُعرض على الشاشة
- يمسح الطالب الكود من هاتفه → يُسجَّل حضوره تلقائياً
- يُغلق المحاضر الجلسة عند الانتهاء

**تعديل سجل الحضور:**
- تغيير حالة أي طالب في أي جلسة لاحقاً

#### 4.23 دفتر الدرجات (Gradebook)

**تهيئة كشف الدرجات:**
- اختيار الشعبة → ينشئ النظام صفوف لجميع الطلاب المسجلين

**إدخال الدرجات:**
- 3 أعمدة لكل طالب: أعمال الفصل / الاختبار الأوسطي / الاختبار النهائي
- حفظ تلقائي للمسوَّدات
- مؤشر التغييرات غير المحفوظة

**نشر الدرجات:**
- تُنشر الدرجات وتصبح مرئية للطلاب
- لا يمكن النشر إذا كان الفصل في حالة تجميد

#### 4.24 منطقة الخطر (Risk Zone)
- عرض الطلاب في خطر (مرتفع / حرج) في شعبه
- إرسال توصية مُخصَّصة للإدارة الأكاديمية بشأن طالب محدد

#### 4.25 التعاميم
- استقبال التعاميم الواردة من الإدارة
- إرسال تعميم لطلابه (كل طلابه أو شعبة محددة)
- إنشاء، نشر، حذف التعاميم

#### 4.26 الرسائل
- **قنوات المقررات**: دردشة للشعب التي يدرّسها
- **محادثات مباشرة**: مراسلة أي مستخدم
- اشتراكات Realtime — الرسائل تظهر فوراً

### 🎓 الطالب (Student)

#### 4.27 لوحة التحكم الشخصية
- المعدل التراكمي (GPA) مع تصنيف: ممتاز / جيد جداً / جيد / ضعيف
- شريط تقدم التخرج (الساعات المكتسبة / الإجمالية)
- الجدول الأسبوعي (الأيام، الحصص، الأوقات)
- قائمة المقررات المسجلة في الفصل الحالي

#### 4.28 مساعد UniBot الذكي
- **واجهة دردشة** مع نموذج ذكاء اصطناعي
- **قاعدة معرفة الجامعة**: يُجيب بناءً على اللوائح والأدلة والسياسات المرفوعة
- **عارض المستندات**: يعرض المستند المصدر جانباً عند الحاجة (قابل للطي)
- **سجل المحادثات**: حفظ ومتابعة المحادثات السابقة
- **حذف المحادثات** من السجل
- ردود مُنسَّقة بـ Markdown (قوائم، عناوين، جداول)

#### 4.29 التكاليف والواجبات
- عرض جميع التكاليف المنشورة في مقرراته
- حالة كل تكليف: لم يُسلَّم / مُسلَّم / متأخر / مُصحَّح
- **تسليم التكليف**: رفع ملف + نص
- **عرض الدرجة والتعليق** بعد التصحيح

#### 4.30 الحضور (من منظور الطالب)
- **تسجيل الحضور بـ QR**: يمسح رمز المحاضر من الكاميرا أو يُدخل الكود يدوياً
- **ملخص الحضور**: نسبة الحضور لكل مقرر مع تحذير عند الاقتراب من حد الحرمان
- **تفاصيل الحضور**: سجل كامل بكل جلسة وحالتها

#### 4.31 الدرجات والسجل الأكاديمي
- عرض درجات جميع المقررات: أعمال فصل / وسطى / نهائي / المجموع
- تصفية بالفصل الدراسي
- المعدل التراكمي الكلي

#### 4.32 المواد التعليمية
- تصفح المواد المُنشرة لكل مقرر
- تصفية بالشعبة أو نوع الملف
- عرض خطة المقرر (Syllabus) الأسبوعية

#### 4.33 التعاميم
- استقبال التعاميم الإلزامية وغير الإلزامية
- مؤشر منتهي الصلاحية والحالة

#### 4.34 الرسائل
- قنوات المقررات المسجل فيها
- محادثات مباشرة مع المحاضرين أو الإدارة
- Realtime — الرسائل الجديدة تظهر فوراً

#### 4.35 نظام التذاكر (طلبات الدعم)
**فتح تذكرة جديدة:**
- الفئة: طعن في درجة / عذر غياب / مشكلة تسجيل / تغيير جدول / مشكلة قاعة / مشكلة تقنية / إداري عام / أخرى
- العنوان والوصف + إرفاق ملف
- **اقتراح AI تلقائي**: يقترح حلاً من قاعدة المعرفة قبل الإرسال

**متابعة التذاكر:**
- رسائل ذهاباً وإياباً مع الإدارة
- تقييم مستوى الدعم بعد الإغلاق (⭐⭐⭐⭐⭐)

## 5. نموذج البيانات (Database Schema — المجموعات الرئيسية)

```
tenants              ← الجامعات (tenant_id عمود التمييز)
subscription_plans   ← خطط الاشتراك
subscriptions        ← ربط جامعة بخطة
invoices             ← الفواتير

profiles             ← جميع المستخدمين (role: super_admin/tenant_admin/academic_management/faculty/student)
student_profiles     ← بيانات إضافية للطلاب (GPA، ساعات)
faculty_profiles     ← بيانات إضافية للمحاضرين (employee_id)

colleges             ← الكليات
departments          ← الأقسام (head_id → faculty)
majors               ← التخصصات (total_credits، duration_years)
academic_levels      ← المستويات (level_number)

courses              ← كتالوج المقررات
study_plan_courses   ← ربط مقرر بمستوى في الخطة
prerequisites        ← المتطلبات السابقة

semesters            ← الفصول الدراسية (حالات: planning/registration/active/grade_freeze/archived)
sections             ← الشعب (open/closed/archived/merged)
```

## 8. ميزات تقنية بارزة

| الميزة | التفصيل |
|--------|---------|
| **Realtime Messaging** | Supabase Realtime يُبث الرسائل الجديدة فوراً لجميع المشتركين |

## 9. ملاحظات للمطورين

- **`requireRole(["role"])`** — middleware يتحقق من الدور قبل أي صفحة
- **Server Components** للجلب الأولي + **Client Components** للتفاعل
- **`window.history.replaceState`** لتغيير URL بدون reload
- **`createServiceClient()`** يتجاوز RLS عند الحاجة لعمليات الخدمة فقط
- جميع صفحات الـ client تستخدم `"use client"` directive
- Server Actions في ملفات `actions.ts` منفصلة لكل وحدة
